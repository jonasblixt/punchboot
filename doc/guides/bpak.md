# bpak in punchboot

Upstream: `../bpak` (github.com/jonasblixt/bpak), currently v1.0.1 (D-024). The file format must
stay backward compatible, permanently (D-008, supersedes D-001). What is frozen: `compatibility.md`.

## What is vendored

- `src/lib/bpak.c` and `include/bpak/{bpak.h,id.h,keystore.h,key.h}` are upstream's **v1.0.1**,
  copied by `scripts/sync-bpak <version>` from the tag and formatted with punchboot's
  clang-format, otherwise unchanged. `include/bpak/version.h` is generated by the script and
  records the version.
- punchboot's own files in their place: `include/bpak/build_config.h` (upstream generates it
  with CMake; no merkle, lzma or mbedtls, no `off_t` size check), `src/lib/internal.h` (the part
  of upstream's `lib/internal.h` that `bpak.c` uses) and `include/libc/unistd.h` (`ssize_t` for
  the firmware).
- `bpak.h` declares the calloc/free hooks and more, which the firmware never defines or calls.
- To update: run the script, check that `src/lib/internal.h` still matches upstream's helpers,
  read the changelog for `bpak_valid_header()` and the lookups (D-008, `compatibility.md`),
  run the tests and the firmware builds, and add golden images for the new CLI.
- The Python package parses the bpak header itself (`tools/punchboot/bpak.py`, D-021).

## What punchboot actually uses

- Header parsing: `bpak_valid_header`, `bpak_foreach_part`, `bpak_part_offset`, `bpak_part_size`, `bpak_get_part`.
- Metadata: `bpak_get_meta*`, only for `pb-load-addr` (u64 per part). `src/boot/atf.c` also uses `optee-arch` (`0x99e5e80a`).
- Board files hardcode part IDs (`atf`, `dt`, `ramdisk`, `kernel`) as hex constants.
- **Signature and payload verification are punchboot's own** (`src/boot/image_helpers.c`). They do not go through bpak's verify code.
  They differ from upstream on `BPAK_FLAG_EXCLUDE_FROM_HASH`: upstream leaves such a part out of the
  hash, punchboot refuses the image before it loads anything (`boot.md` 4.2, D-035).
- Not used: merkle, transport/delta, the bpak crypto and pkg APIs.

## Coupling points

1. `sizeof(struct bpak_header) == 4096` is baked into the LBA math (`boot.c`, `cm_main.c`, `image_helpers.c`). The header sits at the end of the partition.
2. The raw header is sent over the wire protocol.
3. Keystore codegen depends on the output of `bpak generate keystore --decorate` and on the `key.h`/`keystore.h` layouts.
4. The dev container installs the bpak CLI 1.0.1 from PyPI; the vendored copy is the same version.
