## Load and verify time of a 10 MiB image (same branch)

- `scripts/boot-time-image` (host, Python): builds a signed 10 MiB bpak (one `kernel` part,
  SHA-256, P-256) with one payload byte changed after signing, writes it to a partition, boots it
  N times with `boot partition` (pb loads and hashes all of it, then fails with BAD_PAYLOAD, so
  it never jumps on any board), and prints min/median/max per phase from the RAM log. `-c TTY`
  also times resets (host: reset to banner, RAM log: init to `boot_load()`), `-k KEY` signs an
  auth token. jiffy with `-c`: 8 s. `boot_image_load_and_hash()` logs per part the time in
  `read_f` and in `hash_update_async()` (debug), and the time of `hash_final()`.
- imx8mpevk now has the A/B state and the Linux boot driver (jiffy's setup), and a key status
  callback that returns OK (it never writes fuses, so nothing is revoked). Linux can't boot yet
  (no TF-A handover). The first boot found blank PB State partitions and installed the default.
- Results, 5 runs each, within 20 us: jiffy (DDR52): auth 6.3 ms, 10 MiB part 137.9 ms (read
  126.7, waiting for the hash 11.2), final hash 17.2 ms, `Load` to `Prepare` 162 ms. EVK
  (HS200): auth 6.1 ms, part 123.6 ms (read 112.7, hash 10.9), final hash 16.3 ms, total
  147 ms. The read is the bottleneck. The hash of the last 2 MiB chunk is not overlapped:
  smaller chunks than `CONFIG_BOOT_LOAD_CHUNK_kB=4096` would cut most of the ~17 ms. HS200 on
  the EVK reads only ~93 MB/s, not much more than DDR52 on jiffy (~83 MB/s).
- README Metrics: the jiffy and EVK numbers replace the old i.MX6UL tables (400 KB image,
  libtomcrypt); the i.MX8QXP table is unchanged.

## Boot time analysis, step by step (same branch)

Temporary profiling builds (timestamps in imx_usdhc, dwc_ddrphy, plat_mmu_init; not committed),
both boards back on the normal build afterwards.
- eMMC read: one ADMA2 request per 4 MiB chunk. Raw transfer: jiffy 4 MiB in 48.8 ms (82 MiB/s,
  83% of DDR52), EVK 44.3 ms (90 MiB/s in HS200). Cache clean + invalidate per 4 MiB: jiffy 0.88
  + 0.88 ms, EVK 0.33 + 0.33 ms. RD_WML 64 instead of 16 on the EVK: no change.
- Chunk size: 512 KiB on the EVK: last hash 16.3 -> 4.1 ms, hash waits 10.8 -> 0.9 ms, read +4.9 ms
  per 10 MiB (~0.25 ms per command); 10 MiB load+verify 147 -> 130 ms, 29 MiB 365 -> 356 ms.
  Best is ~0.5-1 MiB for 10-30 MiB images.
- jiffy boot ROM: 256 KiB of padding in pb adds 108 ms to reset->banner (127 -> 236 ms): the ROM
  loads and authenticates at ~2.4 MB/s (1-bit eMMC at ~20 MHz?), so the 109 KB image is ~45 ms
  of the 127. HAB keys are RSA-4096 (SRK, CSF, IMG). Image: .text 72 KiB, .ro_data 20 KiB, .data
  4 KiB (4 KiB section alignment), CSF.
- EVK DDR: 1D IMEM load 5.9 ms (0.36 us per 16-bit APB write), DMEM 0.4 ms, PMU start 3.7 ms,
  training 2.9 ms; 2D IMEM 4.7 ms, DMEM 0.3 ms, PMU start 2.6 ms, training 43 ms.
- plat_mmu_init: EVK 3.5 ms reset_xlat_tables (128 KiB memset with the MMU off) + mmap_add, 5.8 ms
  init_xlat_tables; jiffy 5.0 + 8.2 ms. init_xlation_table writes every entry of the tables it
  uses, so the memset looks redundant (to check).

## F-130 found and fixed (same branch)

- usbmon (Jonas: `modprobe usbmon`, `/dev/usbmon1` readable; a small reader in the session
  scratchpad): in the failing `auth` the command OUT and the first result IN complete, the 1024
  byte token OUT ends after 512 bytes with -108 when the watchdog resets pb. With the debug
  dump (EP2 overlay p0 = `align_buffer` + 512, 0 bytes left, though pb's 1024 byte `cm_read`
  had completed): the controller resumed a stale overlay of the previous command transfer.
- Cause: `xfer_start` wrote `qh->next` into a cached dQH line and cleaned all 64 bytes; when
  the line had been filled while the endpoint was primed, the clean put the old active overlay
  back. `log` (16 KB memcpy) changes what's cached, hence the dependency. Fix `3746bc6c`:
  invalidate the dQH line before the write, clear the overlay token (RM 54.4.6.6.3).
- jiffy BOOT0 with the fix (verified): 0 hangs in 1000 `log`+`auth`, 1000 `log`+board command
  with an argument, 300 `log`+`part list`, 200 `log`+`part verify`. imx8dxlevk builds.
- So the D-cache is in use on jiffy (F-135's withdrawn guess stays withdrawn); F-134 is still
  open and unexplained. The debug patch stays in `git stash` ("F-130 debug dump").
