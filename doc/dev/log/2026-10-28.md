## i.MX8M DRAM init (branch `imx8m-dram-cleanup`)

Asked: check whether the imx8m DRAM PHY is the one AMD/Xilinx uses, freshen the code up, add
register definitions, suggest readability/maintainability improvements, and use AMD's docs where
the licence allows.

- **IP:** the controller is Synopsys DWC uMCTL2, the same as the Zynq UltraScale+ PS DDRC
  (0xFD070000): every offset matches AMD's ZynqMP FSBL (`xfsbl_ddr_init.c`, MIT). The PHY is
  **not** the same: ZynqMP has the PUB-based DWC DDR multiPHY (hardware training via PIR), the
  i.MX8M the firmware-trained DWC LPDDR4 PHY (PMU, IMEM/DMEM, mailbox). Versal is AMD's own
  DDRMC. Details and sources in `imx8m-ddr.md`.
- **Licences:** register offsets/fields are facts; the FSBL is MIT, used only to check fields (no
  code copied). UG1085/UG1087 text has no reuse licence: reference only.
- **Test first:** `test_imx8m_ddr` (fake `pb/mmio.h`, device model) records every register write
  and the TF-A copy; the golden trace was taken from the untouched code. All later commits keep it
  identical (checked per commit, plus a firmware compile with placeholder blobs). D-013.
- **Commits:** golden trace test; `bugfix:` training/readback errors ignored (F-098); `bugfix:` PLL
  lock mask UB (F-099, found by UBSan); headers split by IP with fields (`umctl2.h`, `ddrphy.h`,
  `lpddr4.h`, `dram.h`, SRC/GPC in `mm.h`), bogus offset-0x3 defines and duplicates removed;
  training driven by the board's unused `fsp_msg` table, helpers for firmware load, PLL, DFIMISC,
  TF-A copy; board timing as `src/board/imx8mevk/lpddr4_timing.c`.
- **Found, not fixed (need hardware or NXP's DDR tool):** F-101 the board's controller table
  overwrites the 667 MT/s derate/refresh values and never sets the 3200 MT/s ones; F-100 TF-A copy
  leaves `fsp_msg` uninitialized and isn't size checked; F-102 no poll timeouts; F-103 imx8mevk not
  compiled in CI.
- **Left:** the suggestions list in `imx8m-ddr.md`. Nothing was run on an imx8mevk.

## DDR drivers for the i.MX8M Plus and other SoCs (same branch)

Asked: will the i.MX8M Plus and Allwinner H5 use the same controller/PHY, and break the common parts
out of plat/imx8m into drivers selected by the platforms.

- **Checked against U-Boot master** (GPL-2.0+, reference only): the 8MP has the same uMCTL2 and
  firmware-trained PHY (its EVK table writes the same MSTR at 0x3d400000). The H5 has Synopsys
  register names at Allwinner offsets in one window and a PUB-style PHY (`dram_sunxi_dw.c`):
  nothing shared. The H6/H616 have the uMCTL2 at standard offsets. Found F-104 (rank-to-rank
  gaps from training, done by U-Boot on all i.MX8M, missing here).
- **Commits:** `drivers: ddr:` uMCTL2 and DWC PHY drivers (base/stride/firmware passed in),
  `include/plat/imx8m/ddrc.h` generated from the old header (285 addresses compared, identical),

  `PLAT_IMX8M` -> `PLAT_IMX8MQ` + `PLAT_IMX8M_COMMON` (selects the drivers). D-014.
- `DDR_SS_GPR0` is now written only when `MSTR.lpddr4` is set (NXP's condition). Golden trace
  unchanged throughout; jiffy and imx8dxlevk build without the drivers; 22 host tests pass.
- **Left:** `PLAT_IMX8MP` (checklist in `imx8m-ddr.md`, "Adding a SoC"), F-100..F-104.

## Licences (same branch)

- The 2019 imx8m DDR code followed NXP's U-Boot code (GPL-2.0+): verbatim comments and typos
  ("recommened", "Eanble") and 83% of the EVK timing's register/value pairs match NXP's uboot-imx
  2017/2018 files, under a BSD-3-Clause header without NXP's notice. The code files no longer
  contain NXP's text after the rewrite on this branch.
- NXP's BSD-3-Clause TF-A DRAM code (`dram_retention.c`, `dram.c`) has the same reset release and
  controller/DFI steps: those files now reference it and carry NXP's copyright; value differences
  are noted. The firmware load/training code has no BSD source (lower risk, not clean room).
  `struct dram_timing_info` comments reworded. Upstream TF-A doesn't read `fsp_msg` (F-100) and
  reads back the rank-gap registers (F-104).
- F-108 (open): the EVK timing and its golden trace. Can't be regenerated without NXP's DDR tool
  (the PIE image and PHY config come from Synopsys' PHY init inside it); the tool's output licence
  must be checked first. Steps in `imx8m-ddr.md`, "Licences and provenance". The 8MP checklist now
  says not to use U-Boot's GPL 8MP EVK timing.
