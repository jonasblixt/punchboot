# 2026-10-28

## RAM log and `punchboot log` (branch `ramlog`, v2.8.0)

- `CONFIG_RAMLOG`: a copy of the console output in a ring buffer in `.no_init` (`ramlog`,
  `struct pb_ramlog_hdr`). `ramlog_init()` is the first call in `main()`, so prints before
  `console_init()` go to the log only and are replayed to the UART by `console_init()`.
  Checked on jiffy: the ramlog read over JTAG matched the UART capture byte for byte.
- `CONFIG_RAMLOG_LOGLEVEL` (default debug): levels above `CONFIG_LOGLEVEL` go to the log only,
  the LOG macros mute the UART around them, and the replay skips the ones muted before
  `console_init()` (32 slots). `LOG_MAX_LEVEL` guards log-only helpers. On jiffy with the UART at
  info: 2.4 KB on the UART up to `boot()` instead of 5.7 KB, and the ramlog minus its debug lines
  equals the UART output. Size: 90112 bytes (UART info, RAM debug) against 81920 without.
- `PB_CMD_LOG_READ` (appended, D-008): absolute positions since `ramlog_init()`, the host reads
  up to the first reply's head. Old devices answer `INVALID_COMMAND`, which the host maps to
  "not supported" (checked against 2.7.1 on jiffy). Needs auth on a locked device.
- `punchboot log [-o FILE]`, `pb_api_log_read()`, `Session.log_read()`.
- pb-host's stdout goes through `console_putc()` (`fopencookie()`), so the host ramlog equals the
  pb-host log. The stream is opened after the RAM `mmap`: as the first `malloc()` it set up the
  brk heap, whose start is randomized over 1 GiB on x86-64 and sometimes landed on 0x40000000
  (flaky integration tests). Seen only in non-ASan builds: ASan's allocator doesn't use brk.
- Bugfixes: pbstate took its version (0.3.3) from its own CMakeLists.txt, now `version.txt` with
  the SONAME pinned at 0; `include/pb/console.h` had no working include guard.
- Testing on jiffy without flashing: OpenOCD halts Linux, a write to WDOG1_WCR (physical
  address) resets into the serial downloader (F-078), `pbdebug`-style load, and `boot()` made to
  return at a hardware breakpoint gives command mode over USB. Auth token: ECDSA P-256 over the
  device UUID string with `pki/secp256r1-key-pair.pem` (`pb-development`). OP-TEE panics in its
  CAAM init after a JTAG load (no HAB, so no MID unlock from the CSF).
- Left: F-109; decision ids D-013 and up collide across branches (`doc-decisions`,
  `nanopi-neo-core2`, `pbi-image-format`), renumber when they merge.
