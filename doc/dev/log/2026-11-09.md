### Revoke slots (F-165)

A key's revoke slot was its place in the keystore. A product that revokes key 0 and then drops
it from the keystore moves key 1 onto slot 0's burnt bit: pb rejects every image signed with it.
`CONFIG_KEYSTORE_SLOTS` lists the key ids in slot order (Jonas chose this over a documented rule
or a slot in the keystore bpak, which needs bpak changes). A dropped key keeps its place in the
list. `rot_init()` refuses a list it can't parse or without a slot for a keystore key, empty
is the keystore's order. Set in the host, jiffy, MEK and RT1060 defconfigs to the keystore's
order (no change on those devices); the DXL EVK's own `keystore.bpak` isn't in the tree, it stays
empty. `rot_key.index` is `slot`. `test_rot_slots` (includes `rot.c`, sets the list per test).
35 host test suites, 6 boards build, RT1060 MCU test bench 7/7.

### Configuration fuses as data

The boards' `set_configuration` fused the SRK hash, then wrote their boot fuses, again on every
call. Now:
- `slc_config.fuses` lists the words (fuse index, bits) with the platform's `fuse_read` and
  `fuse_write`. `slc_set_configuration()` calls the platform's `set_configuration` (the SRK
  hash: `imx_hab_slc_set_configuration()`, `imx8x_slc_set_configuration()`), then sets the bits
  of each word that aren't set yet. A word with all of them is skipped, also with other bits in
  it (the 6UL's BT_FUSE_SEL shares the closed bit's word). A read or write error stops it.
  `slc_init()` refuses fuses without a read and a write.
- `imx_ocotp_fuse_read/write()` by index, `IMX6UL_FUSE(bank, word)`. `srk_fuse.c` is always
  generated, empty without `CONFIG_SRK_FUSE`; the SRK writers refuse an empty hash.
- `test_fuse_read()` returns the value through a pointer: a host fuse word with bit 31 set read
  as an error.
- Converted: host, jiffy, MEK, DXL EVK (separate commits). Unit tests `test_slc_fuses`,
  `test_slc_fuses_config`, the HAB driver's `imx_hab_slc_set_configuration()`.

Checked: 35 host test suites, the 6 boards build. jiffy runs it from BOOT0: SLC LOCKED, the three
keys active, authentication needed. No SLC write was run on any board; the fuse path is only

### One handover on every arch, the simple boot driver (D-028)

- `include/pb/arch.h` documents what every arch gives the next stage and declares
  `arch_disable_mmu()`, `arch_invalidate_icache()` and `arch_jump()` once: the MMU (MPU) and the
  D-cache off, the I-cache invalidated, interrupts masked, the exception level pb runs at (EL3 on
  the 8M and 8X), p0..p3 in r0-r3/x0-x3. Every `arch_jump()` masks interrupts and invalidates the
  I-cache; every arch has `arch_invalidate_icache()`; the ARMv7-A `arch_disable_mmu()` masks IRQ
  and FIQ first.
- ARMv7-M `arch_disable_mmu()` was empty and the RT1060 handed over with the D-cache on (the ROM
  turns it on, CCR 0x70200) and PRIMASK 0. It is assembly now (`src/arch/armv7m/mmu.S`): PRIMASK,
  MPU off, clean and invalidate by set/way, D-cache off, invalidate, with no store to normal
  memory in between (as on ARMv8-A).
- `bugfix:` ARMv7-A `arch_jump()` put r4 in r3 (p3 is on the stack), ARMv8-A set x3 to 0. No
  caller passes p3.
- `armv7m_baremetal` is `simple` (`boot/simple.h`, `CONFIG_BOOT_SIMPLE`, `board.boot_simple`),
  pb's simple boot protocol; "baremetal" said something about the image. Nothing in it was
  ARMv7-M's. It compiles for ARMv7-A and ARMv8-A
  (checked with jiffy and imx8mpevk defconfigs that enable it). It no longer cleans the image or
  invalidates the I-cache itself.
- MCU test app: PRIMASK 1, CCR.DC 0 and MPU_CTRL 0 are checks; against the old pb the first two
  fail, the new pb passes 7/7 (entry: PRIMASK 1, CCR 0x60200, the I-cache on).
- Checked: 36 host test suites, 6 boards build; jiffy, the 8MP EVK and the MEK boot Linux to the
  login (TF-A on the 8M/8X), all back in command mode. The MEK's `part write` failed twice before
  it went through (F-159).
