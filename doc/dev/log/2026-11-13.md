### The block device core (F-182, F-283, F-193)

- **F-182**: the core owns a length that isn't whole blocks. It has a block buffer
  (`CONFIG_BIO_MAX_BLOCK_SIZE`, 4096 by default, in `.no_init`): a write's last partial block
  goes through it padded with zeros, a read's is trimmed. The drivers refuse a length that
  isn't whole blocks, the fakes too. Command mode is unchanged: hosts send raw sizes, and
  the core makes them whole.
- A conformance suite's start, `tests/unit/conformance/`: five tests against eight devices

- **F-283**, seven commits: a largest block size, a length of 0, a second `mmc_init()`, a
