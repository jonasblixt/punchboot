## F-084: GPT tick 2.64x fast on jiffy

- Measured over JTAG (AHB mem-AP, core running): GPT1_CNT advanced 26518521 in 10.044 s of
  host time, 2.6401 ticks/us. The ROM leaves perclk on IPG at 66 MHz (CSCMR1 `0x04900000`,
  CBCDR `0x00018900`, CBCMR `0x24a69324`, PFD_528 `0x5058505b`), and `imx_gpt_init()` wrote
  PR = 24, which divides by 25. 66 / 25 = 2.64. The RM's "default 49.5 MHz" IPG doesn't apply:
  the ROM sets AHB_PODF to 3.
- Fixed in four commits: `bugfix:` PR + 1 (all platforms), register and bit names (no
  functional change, same jiffy object code), `imx_gpt_init_24m()` plus the RM 28.5.1 init
  sequence and a rate range check, `bugfix:` imx6ul uses the crystal, `bugfix:` imxrt passes
  perclk instead of IPG.
- Every commit builds for jiffy and imx8dxlevk. Host tests pass (they don't cover the driver).
- Checked on jiffy (Jonas flashed `c1a8408`): GPT1 CR `0x743`, PR `0x7002`, GPT1_CNT advanced
  10046344 in 10.046 s of host time, 1.0001 ticks/us. perclk still reads 66 MHz, so the tick no
  longer depends on it.
- Left: check the GPT perclk on imx8x/imx8m. JTAG on the closed board blocks the CAAM until a

## F-005, F-063, F-094 (host-supplied sizes)

- F-005: `cmd_auth` passed the host's size (up to 65535) to the token check and the password
  callback, and ignored the read result, so a lost transfer checked the last good token again.
  Size 0 or over 1024 is now refused before the first result; every released host (1.x and 2.x)
  checks that result before sending, so no valid exchange changes.
- F-063: `cmd_board` passed `request_size` (up to 4 GiB) to the board; 0xffffffff crashed pb-host
  (`arg[size] = 0`). Over 1024 is refused after the request transfer, because 2.x hosts send it
  without checking the first result.
- F-094 (new, host): `internal_pb_api_authenticate` overflowed its stack buffer for a token over
  1024 bytes (64 KiB: SIGSEGV) and reported size 0 as success. Now INVALID_ARGUMENT before
  sending. Tested against a fake old device in its own process: the extension holds the GIL during
  I/O (F-009), so a thread deadlocks.
- F-095 (new, open): `cmd_board` ignores `response_buffer_size`; an oversized response desyncs the
  host.
- Each fix's tests fail without it. All host tests pass, also with ASan/UBSan; jiffy and
  imx8dxlevk build. `cm: name the buffer and data transfer sizes` is cosmetic (same jiffy code).
