## Phase 0: dev container

- Docker Engine (docker-ce) installed on the workstation.
- Added `docker/Dockerfile`, `scripts/pbdev` (image tag = hash of `docker/`) and
  `scripts/ci/test.sh`. bpak v0.9.3 builds fine against Debian's Mbed TLS 3.6.
- The first run crashed in `test_part` (`*** Abort` at DFAR 0x841b0001). Investigation:
  - Jonas suspected the gcov hack. It was broken twice over: GCC 14 has 9 counters (F-013), and
    the counter record length has been in bytes since GCC 12 (F-014). Both fixed. Verified with
    gcov-dump, and the counts merge across boots.
  - The crash itself was F-012: the A/B state callbacks ran with a NULL config after a failed GPT
    init. It used to "work" because the older QEMU on the CI runner apparently had harmless contents at that address (not verified).

  `$(CROSS_COMPILE)gcov`.
- Result: 43/43 tests pass, coverage 54% of lines.

## Fixed F-053, F-054, F-056

- Test teardown now fails on a non-zero pb-host exit or a sanitizer report in the log. Before, the
  reset at teardown hid them. No existing test had a hidden report.
- `pbtest.Wire` (`device.wire()`): raw wire client. `test_stream.py` covers stream buffer id, size and
  offset bounds. 12 of its 13 tests failed before the fix; the end-of-partition one failed because
  `bio_write` returned `-PB_ERR_IO` for range errors while `bio_read` returned `-PB_ERR_PARAM`.
- `stream_check()` in `cm_main.c` bounds buffer id/size/offset. A failed stream read no longer sends
  two results (the second one desynced the host).
- `check_lba_range` uses 64-bit arithmetic (`test_bio.c`).
- GPT headers with more than 128 entries or entries that aren't 128 bytes are rejected, and the entry
  loop is bounded (`test_gpt.c`; ASan reproduced the overflow before the fix).
