- **The lock.** `gpt.c` keeps the handles it made at the set up (one run of them) and compares

  `bio_erase()` of its partitions answer `-PB_ERR_STATE` (`ERROR` on the wire), and the log
  says to reset. Not the device itself (the table is written there, a second install
  works) and not other devices (an eMMC's boot partitions: a factory flow that writes pb's
  boot partition after the install, before the reset, worked in every release). Sticky until
  the reset; an install that fails while it writes a changed table locks too.
- **For the field** (D-008): the same wire and the same bytes on the medium. Reinstalling the
  layout that is on the device locks nothing. A host that writes after an install that
  changed the table gets `ERROR` where a release wrote at the old blocks.

  layout locks, the same one doesn't, a refused one and a failed write), `test_gpt.py` (a

## The 8X's ROM, SECO and SCU logs, with peek (the MEK)

Jonas: use peek on the 8X to find logs from the ROM, the SECO or the SCU.

- **The mapping**: `src/plat/imx8x/plat.c` maps, with `CONFIG_HACK_PEEK` only and read only as
  device memory, the OCRAM (0x00100000, 256 KiB) and the SCU's TCM as the system sees it
  (TCML 0x30fe0000, TCMU 0x31000000, 8QXP RM 2.2.8.1; the 8DXL RM has the same addresses).
- **On the MEK**: a pb of this tree with peek, built with the test bench's tools, in BOOT1
  (`part write` enabled it). The boot partitions can't be read back (F-083), so no backup.
  - The OCRAM: all 256 KiB are power-up noise (entropy 7.7 bits a byte, no container header, no
    run of zeros). Neither the ROM nor the SCFW uses it on a boot from the eMMC.
  - The SCU's TCM: a read at 0x3101ff00 (the 256 bytes the ROM keeps, RM 5.7.3.7) and one at
    0x30fe0000 are synchronous external aborts (ESR 0x96000210, DFSC 0x10): the SCFW's XRDC
    lock, as the RM says. pb stops in its handler and the watchdog resets it after 10 s. So the
    ROM's log (AN12853: the pointer at 0x5e0 of the SCU's ROM, four buffers of 128 words in its
    TCM) is out of the A35's reach.
  - The SCU's UART (the FTDI's if01) printed nothing through two resets: this SCFW (5665) has no
    console.
  - What the A35 has is the SCFW's API: the SECO's events and life cycle (the log `seco`,
    already), the boot type (already). `sc_misc_get_boot_container()`, which container set the
    ROM booted, is in the vendored client and pb doesn't call it: a candidate for `info`.
- **The board afterwards**: BOOT0 rewritten with the test bench's image of the pb it had
