## An installed table is in effect after the reset (D-093)

Jonas: revert F-194's "in effect at once" (`6cb29af9`, D-070), it added more than it is worth.
A reset is required; a flag that locks the writes when the table changed, with a warning.

- **D-093** replaces D-070's "A". `bio.md` 4, `command-mode.md` 5.3, `board.md` 2.4 and 6,
  `boot.md` 3.1, `porting.md` 2.6, the migration guide and `CHANGELOG.md` say it.
- **The revert**, by hand: the code had moved since (`cm_main.c` in pieces, `readable_parts`,
  F-283's block sizes). Gone: the released partitions and dead handles, `table_flags`, the
  pending partitions, `boot_policy_reinit()`, the stream's end at the install, the
  partitions an install made. Kept: `gpt_make_partitions()` as a function, the table's read
  that tries every handle.
- **The lock.** `gpt.c` keeps the handles it made at the set up (one run of them) and compares
  the new layout before it writes: the number of partitions, each UUID among them, its
  blocks. Names, types and attributes don't count. When it differs it calls
  `bio_set_table_changed()` on the device: from then until the reset `bio_write()` and
  `bio_erase()` of its partitions answer `-PB_ERR_STATE` (`ERROR` on the wire), and the log
  says to reset. Not the device itself (the table is written there, a second install
  works) and not other devices (an eMMC's boot partitions: a factory flow that writes pb's
  boot partition after the install, before the reset, worked in every release). Sticky until
  the reset; an install that fails while it writes a changed table locks too.
- **For the field** (D-008): the same wire and the same bytes on the medium. Reinstalling the
  layout that is on the device locks nothing. A host that writes after an install that
  changed the table gets `ERROR` where a release wrote at the old blocks.
- **Tests**: `test_bio` (the lock, an install that does and doesn't lock), `test_gpt` (another
  layout locks, the same one doesn't, a refused one and a failed write), `test_gpt.py` (a
  blank device's partitions after the reset; another layout: the old partitions listed,
  write and activation refused, verify works, the log, written after the reset; the same
  layout three times; refused layouts). `test_part.py`'s comment back to "after the reset".
- **F-470** (new): a partition starts with its device's flags, `READABLE` too. No board's table
  device is on its list. **F-423** closed: what it had left was the install's machinery.
- Fixed beside it: `roadmap.md`'s `docs/format.md` (yesterday's commit) failed the lint.
